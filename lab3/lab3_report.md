## 1. 实验整体逻辑

本实验在物理内存初始化之上实现完整的 Trap 处理闭环。启动时先清空 BSS、读取 DTB 并初始化控制台，设置 `stvec` 指向 `__alltraps`，初始化物理页管理，然后设置定时器并开启 S 态中断。Trap 到来时，硬件写入 `sepc/scause/stval`，更新 `sstatus`，跳到汇编入口；汇编保存上下文、调用 C 层 `trap(tf)`；C 层按原因处理；汇编恢复上下文并执行 `sret`，回到被打断的位置或调整后的异常返回地址。

本实验仍使用内核栈和内核态执行流，不涉及用户栈与内核栈切换。框架默认启用 First-Fit；指导书要求继承的 Lab 2 页初始化及 Best-Fit 实现也已补齐。

## 2. 功能模块一：上下文恢复及 Trap 入口

代码位置：`kern/trap/trapentry.S`。

### Spec

以现有 `SAVE_ALL` 和 `struct trapframe` 为接口依据：RV64 下每槽 8 字节，共 36 槽、288 字节，前 32 槽对应 x0 至 x31，后四槽依次为 `sstatus/sepc/stval/scause`。不得改变保存布局和 `trap(struct trapframe *tf)` 签名。恢复所有可写通用寄存器以及返回需要的 CSR；通过 a0 传递帧指针；最后执行 `sret`。

### 本次使用的实现提示约束

本次请求是“根据 lab3 实验指导完成 lab3”。据此整理的实现约束为：读取 SAVE_ALL 与 trapframe，补齐 RESTORE_ALL 和 __alltraps；先恢复 sstatus/sepc，再恢复通用寄存器，最后加载原 sp；a0=当前 sp，调用 trap；保持栈对齐及原有保存逻辑。此段是本次实现约束的整理，不是另一次模型对话的逐字记录。

### 核心实现理解

`SAVE_ALL` 先把原 sp 暂存到 `sscratch`，分配帧空间，再把原 sp 存入第 2 槽。`RESTORE_ALL` 用当前 sp 定位帧，先用 s0/s1 作为临时寄存器恢复 `sstatus/sepc`，随后从帧恢复 s0/s1 等寄存器自身的旧值。sp 必须最后恢复，否则后续 LOAD 将相对错误的地址取数。x0 恒为零，无需恢复；`scause/stval` 是诊断信息，无需为返回而写回。

`__alltraps` 中 `mv a0, sp` 把帧首地址作为第一个 C 参数，再 `jal trap`。调用覆盖的 ra、a0 等值已保存在帧中，返回后由恢复宏取回。帧大小 288 是 16 的倍数，符合调用时栈对齐要求。`sret` 根据 sepc 恢复 PC，并根据 SPP/SPIE 恢复特权级及中断使能状态。

## 3. 功能模块二：中断与异常处理

代码位置：`kern/trap/trap.c`。

### Spec 与提示约束

根据 `scause` 最高位区分中断和异常；处理中断时屏蔽该位取得原因码。S 态时钟中断应重设下一次事件、使 ticks 每次加一，每 100 次输出 `100 ticks`，累计输出达到阈值后调用已有 SBI 关机接口。识别其他框架定义的软中断、时钟中断及外部中断，未知原因打印帧。非法指令、断点需输出对应地址并跳过触发指令；其他异常打印帧。

实现提示约束为：使用框架现有 IRQ/CAUSE 宏和接口，不改 trap_dispatch、trap、print_ticks 等函数；不能遗漏定时器重置；根据指令低两位区分本实验使用的 16 位与 32 位指令，更新帧中的 epc；未知异常使用已有打印函数兜底。指导书提到 SHUTDOWN_AFTER，但课程包没有定义其数值，因此本实现补为 10，即累计 1000 次时钟中断关机。

### 核心实现理解

`trap_dispatch` 把 cause 转为有符号数，负数表示最高位为 1，分派至 `interrupt_handler`。后者屏蔽最高位并 switch 分类。处理 `IRQ_S_TIMER` 时先 `clock_set_next_event()`，然后更新 ticks，整百时输出，达到阈值调用 `sbi_shutdown()`。定时器接口只安排一次事件，因此每次中断都必须重新安排。

`exception_handler` 对非法指令与断点输出 `Illegal instruction at ...` 或 `Breakpoint at ...`。从 epc 读取 16 位半字，低两位为 11 时本实验按 4 字节前进，否则按 2 字节前进。这样既支持压缩断点，也支持普通 32 位断点和本实验的非法 32 位指令。该恢复策略针对课程测试中的可读内核指令地址和 16/32 位编码，不提供任意长指令或不可读用户地址的通用异常恢复。

时钟中断不修改 epc，因为它是异步发生的，应继续执行原程序；断点和非法指令需跳过，否则返回后会再次触发同一异常。

## 6. 实验知识与 OS 原理的对应

| 实验机制 | 对应原理 | 含义与区别 |
| --- | --- | --- |
| trapframe 与 SAVE/RESTORE | 现场保护与恢复 | 硬件只维护部分 CSR，软件补存通用寄存器；本实验没有进程切换。 |
| stvec、scause、分派函数 | 中断向量与中断分类 | 框架使用 Direct 入口，再由软件分派。 |
| sepc 与异常指令长度 | 同步异常恢复 | 异常由当前指令触发，需明确重试或跳过；实验采用跳过。 |
| SIE、SPIE、SPP、sret | 特权控制与中断屏蔽 | 硬件进入 Trap 时屏蔽 S 态中断，返回恢复先前状态。 |
| SBI 定时器与 ticks | 时钟中断和时间管理 | time 是平台计时源；ticks 记录已处理次数，处理延迟会造成时间偏差。 |
| local_intr_save/restore | 临界区保护 | 单核避免中断重入；不能单独提供多核互斥。 |
